# 跳跃手感设计 · 平衡与验证（v0.1）

> 设计哲学：手感不是"感觉对了就行"，而是**可调参数面 + 可测量的平衡指标**。
> 每个数值都是 `[PLACEHOLDER]`，待 playtest 用真实体感再校准；改一个常量即可，不必动逻辑。

## 1. 问题（改前）
- 跳高 `JUMP_FORCE²/(2·GRAVITY)` = `9.5²/0.9` ≈ **100px ≈ 4.2 格**，又高又飘（滞空 ~0.7s）。
- 对称重力、无上升沿/可变跳高/土狼/缓冲 → 表现为"发射式 launch + 踩空漏跳 + 提前按丢跳"。
- 玩家对象无 `isPlayer` 标志，重力曲线无法只对玩家生效（会误伤掉落物/怪物）。

## 2. 手感系统（5 个，全部开关式可调）
| 系统 | 常量 | 值 | 作用 |
|---|---|---|---|
| 满跳高度 | `JUMP_FORCE` | 8.0 | 起跳速度；满跳 ≈ 2.86 格 |
| 可变跳高 | `JUMP_CUT` | 0.45 | 上升中松键→速度×0.45，轻点小跳、长按满跳 |
| 下落更快 | `FALL_GRAVITY_MULT` | 1.4 | 下落重力 ×1.4（fast-fall），手感更"紧" |
| 顶点悬停 | `APEX_GRAVITY_MULT` / `APEX_VY` | 0.55 / 1.6 | 接近顶点(|vy|<1.6)重力×0.55，轻微滞空 |
| 土狼时间 | `COYOTE` | 6 帧(0.1s) | 离地后仍可起跳，悬崖边不漏跳 |
| 跳跃缓冲 | `JUMP_BUFFER` | 7 帧(0.12s) | 落地前提前按下不丢失 |

> 仅玩家生效：重力曲线在 `moveEntity` 内用 `e.isPlayer` 守卫，掉落物/怪物重力不变。

## 3. 当前平衡指标（headless 仿真 `_test_jumpfeel.js` 实测）
| 指标 | 改前 | 改后 | 目标窗 |
|---|---|---|---|
| 满跳高度 | 4.2 格 | **2.86 格** | 2.8–3.2 |
| 轻点高度 | 同满跳(无) | **1.09 格**（极轻 0.88） | <1.3 |
| 满跳滞空 | ~0.70s | **0.58s** | <0.75 |
| 上升/下降半程 | 对称 | **20 / 15 帧** | 下降更短 |
| 土狼可起跳 | 否 | **是** | 是 |
| 落地前按触发 | 否(丢跳) | **是** | 是 |

## 4. 平衡验证路径（playtest 落地方法）
1. **满跳**：贴墙放标记，跳起量高度 ≈ 3 格；若觉得"跳不上 3 格台阶"→ 调 `JUMP_FORCE` +0.5 步进。
2. **可变跳高**：轻点应刚好上 1 格、长按 3 格；若轻点仍高 → 降 `JUMP_CUT`(如 0.35)。
3. **fast-fall**：下落应明显比上升"砸"得快；若仍飘 → 升 `FALL_GRAVITY_MULT`(如 1.6)。
4. **土狼/缓冲**：悬崖边晚 0.1s 按、落地前 0.12s 按都应响应；若漏 → 各 +2 帧。
5. **顶点悬停**：最高点应有极短"顿一下"；若顿太久/太短 → 调 `APEX_GRAVITY_MULT`/`APEX_VY`。
