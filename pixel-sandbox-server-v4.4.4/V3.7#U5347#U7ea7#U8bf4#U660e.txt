Pixel Sandbox V3.7 —— 核心合并版

==================================================
本版是什么
==================================================
V3.1~V3.6 的模块（权限、玩家列表、Kick/Ban、管理操作）此前都是
独立文件，从未接入主服务器，功能没有真正生效。
V3.7 把它们全部真正合并进 server.js，并通过 36 项自动化测试。

==================================================
已完成（全部真实生效）
==================================================
【服务器 server.js —— 已重写为合并版，原文件备份为 server.js.v3.4.bak】

1. 权限系统（player / admin / developer）
   - 身份按昵称绑定，持久化在 server/data/roles.json，重启不丢
   - 开发者默认：创造模式 + 飞行 + 无限物品标记
   - 名字前缀：[管理员] / [开发者]，全服广播同步

2. Kick（5 分钟限制）
   - 踢出后 5 分钟内无法重进，持久化在 data/kicklist.json
   - WS 和 HTTP 两种模式加入时都会检查，提示剩余分钟数

3. Ban（直到解除）
   - 持久化在 data/banlist.json，重启不丢（旧版只存内存）
   - /api/op/unban 解除后立即可重进

4. 创造模式
   - 开发者自动创造模式；管理员可用 /api/op/setmode 给任何人切换
   - 模式变更实时广播 mode_update，客户端即时收到

5. 聊天
   - 按 T 打开输入框，Enter 发送，Esc 取消（左下角消息记录）
   - 消息带身份前缀；管理员/开发者可发公告（channel=announce）
   - 限速 500ms 防刷屏；单条最长 120 字；管理员可全局关闭聊天
   - HTTP 轮询模式走 /api/chat，功能一致

6. PVP
   - 服务端总开关（data/config.json，默认关闭）
   - 关闭时攻击直接被拒（pvp_denied）
   - 开启后校验：伤害上限 20（防伪造高伤害）、距离上限约 12 格（防全图秒杀）
   - 被攻击方实时收到 pvp_hit 并扣血

7. 管理 API 鉴权（安全修复）
   - 旧版 /api/kick、/api/ban、/api/reset、/api/save 任何人都能调用
   - 本版全部要求 opToken 登录态，未登录一律 403

8. 管理日志
   - 踢出/封禁/解封/改身份/改模式/改配置/公告 全部落盘 data/admin-log.json

9. 在线玩家列表
   - player_list_update 广播：加入/离开/身份变更实时推送
   - 含昵称、身份、前缀、模式、血量（客户端 HUD 在 V3.8 做）

10. 新增管理接口
   - /api/op/status    服务器状态（在线数/内存/运行时长/配置）
   - /api/op/setrole   设置身份（player/admin/developer）
   - /api/op/setmode   切换生存/创造
   - /api/op/config    世界开关（pvp/chatEnabled/creativeModeControl/playerListDisplay）
   - /api/op/announce  全服公告
   - /api/op/log       最近 50 条管理日志

【客户端 game.js —— 已接入新协议】
   - 聊天框 UI（动态创建，无需改 index.html）
   - 头顶名字显示身份前缀（管理员金色 / 开发者青色）
   - 接收 role_update / mode_update / config / pvp_hit / player_list_update
   - welcome 下发身份与模式，管理员/开发者加入时有身份提示
   - 被封/被踢时明确提示原因，不再盲目重连
   - 控制台测试钩子：sendPvpHit(目标id, 伤害)

【修复】
   - ws.on('error') 引用未定义变量 p 会崩服的问题
   - 旧版 Ban 重启失效的问题
