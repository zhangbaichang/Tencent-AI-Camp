# 像素沙盒 — 游戏系统设计文档

> 版本：0.3 Alpha | 日期：2026-08-07 | 作者：系统设计 Agent

## 一、Fun Hypothesis（趣味假设）

> **"玩家在沙盒世界中挖掘收集的材料，不仅是建造的素材，更是战斗的弹药——当你发现煤矿+火把能触发'燃烧'反应造成双倍伤害时，整个世界的每一块方块都变成了潜在的战术资源。"**

### 假设拆解

| 子假设 | 验证方式 | 预期信号 |
|--------|---------|---------|
| H1: 材料即弹药的循环让挖矿有目的感 | 观察玩家是否为了战斗主动挖矿 | 玩家在战斗前主动储备特定元素材料 |
| H2: 元素反应的发现带来"啊哈"时刻 | 追踪玩家尝试组合的次数与反应触发率 | 首次反应触发后，玩家尝试组合数显著上升 |
| H3: 反应翻倍的奖励足够诱人但不必要 | 比较有反应/无反应的击杀效率 | 无反应也能击杀，但反应让击杀效率提升40-60% |
| H4: 材料消耗带来的风险-回报张力有趣 | 观察玩家是否在"用掉稀有材料战斗"和"留着建造"之间犹豫 | 玩家在低血量时才愿意消耗稀有材料 |

### 证伪条件
- 如果玩家普遍只用拳击（不消耗材料的 fallback），说明材料消耗的惩罚太重
- 如果玩家从不尝试组合，说明反应系统的反馈不够明显
- 如果反应伤害让战斗变得无脑（一击秒杀），说明数值需要收紧

## 二、Design Pillars（设计支柱）

### Pillar 1: 万物皆弹药（Everything is Ammo）
世界中每一种可收集的方块都有元素属性，都可作为战斗卡牌使用。挖矿不仅是建造的前置，更是战斗准备。这意味着玩家的探索行为同时服务于两个系统。

**设计约束**：任何新方块的加入都必须考虑其对战斗平衡的影响。

### Pillar 2: 反应即发现（Reactions are Discoveries）
元素反应不是教程教出来的，是玩家试出来的。对战面板提供"元素反应速查表"作为参考，但具体哪些材料能组合出什么反应，需要玩家在实践中验证。

**设计约束**：反应规则必须符合直觉（火+木=燃烧），不能为了复杂而复杂。

### Pillar 3: 消耗即决策（Consumption is Decision）
每次攻击消耗材料。用掉4个钻石砖去打一只30HP的史莱姆是否值得？这个权衡让战斗不是无脑选最强卡牌，而是根据敌人强度和材料储备做决策。

**设计约束**：必须有 fallback 路径（拳击5伤害），确保玩家永远不会陷入"有材料但不敢用、不用又打不过"的死锁。

### Pillar 4: 夜晚即压力（Night is Pressure）
白天是安全的探索和收集时间，夜晚是战斗和生存测试。昼夜循环创造节奏变化，避免单调。

**设计约束**：夜晚的威胁必须与玩家的准备程度成正比——初期夜晚是恐怖的，后期夜晚是刷材料的时机。

### Pillar 5: 深度即奖励（Depth is Reward）
越深的矿洞有越稀有的矿石，稀有矿石对应更强的元素属性（钻石=crystal，金=metal）。鼓励玩家冒险深入，而不是在地表安全 farming。

**设计约束**：深度带来的收益增长必须快于风险增长，否则玩家会停留在浅层。

## 三、核心循环拆解

```
┌─────────────────────────────────────────────────────────────┐
│                     CORE GAME LOOP                          │
│                                                             │
│   ┌──────────┐    ┌──────────┐    ┌──────────┐            │
│   │ EXPLORE  │───▶│  GATHER  │───▶│  CRAFT   │            │
│   │ 探索世界  │    │ 挖矿/砍树 │    │ 合成/冶炼 │            │
│   └──────────┘    └──────────┘    └──────────┘            │
│         ▲                               │                   │
│         │                               ▼                   │
│   ┌──────────┐    ┌──────────┐    ┌──────────┐            │
│   │ PROGRESS │◀───│  REWARD  │◀───│  BATTLE  │            │
│   │ 解锁/成长 │    │ 掉落/分数 │    │ 卡牌对战  │            │
│   └──────────┘    └──────────┘    └──────────┘            │
│         │                               ▲                   │
│         │                               │                   │
│         └─────── NIGHT TRIGGER ─────────┘                   │
│                  夜晚生成敌人                                 │
└─────────────────────────────────────────────────────────────┘
```

### 循环步骤详解

| 步骤 | 玩家行为 | 系统响应 | 时长预期 |
|------|---------|---------|---------|
| 1. EXPLORE | 移动、查看地形、寻找矿脉 | 渲染世界、光照变化、揭示矿石 | 30-60秒 |
| 2. GATHER | 挖掘方块、砍树 | 硬度判定、粒子反馈、物品入栏 | 10-30秒/块 |
| 3. CRAFT | 打开合成菜单、选配方 | 消耗材料、产出新方块 | 5-10秒 |
| 4. BATTLE | 选牌、检查反应、攻击 | 伤害计算、元素反应、动画反馈 | 15-30秒/场 |
| 5. REWARD | 拾取掉落 | 煤矿入栏、Toast提示 | 2-3秒 |
| 6. PROGRESS | 继续探索更深处 | 更稀有矿石、更危险敌人 | 持续 |

### 循环周期
- **微循环**（30秒）：挖矿 → 入栏 → 继续挖
- **中循环**（2-5分钟）：收集 → 合成 → 建造/装备 → 探索更深
- **大循环**（10-15分钟/昼夜）：白天收集 → 夜晚战斗 → 获得掉落 → 白天探索更深

## 四、经济系统：源与汇

### Sources（资源来源/产出）

| 源 | 产出物 | 产出速率 | 条件 | 备注 |
|----|--------|---------|------|------|
| 挖矿-地表 | 泥土、沙子、原木 | 高（硬度6-10） | 无限制 | 初期主要来源 |
| 挖矿-浅层 | 煤矿、铜矿 | 中（硬度20-22） | 深度5-50 | 战斗弹药核心来源 |
| 挖矿-深层 | 铁矿、金矿 | 低（硬度28-30） | 深度25-100 | 需要火把照明 |
| 挖矿-深层 | 钻石矿 | 极低（硬度40） | 深度100+ | 最强战斗材料 |
| 合成-手工 | 木板、火把、石砖 | 消耗原材料 | 无 | 基础工具 |
| 合成-工作台 | 门、箱子、栅栏、砖 | 消耗原材料+工作站 | 需工作台 | 建筑扩展 |
| 合成-熔炉 | 玻璃、金属锭、钢 | 消耗矿石+煤+熔炉 | 需熔炉 | 战斗材料升级 |
| 战斗掉落 | 煤矿×1 | 每次击杀 | 击杀敌人 | 唯一的"可再生"矿源 |
| 初始携带 | 无 | — | 新建世界 | 玩家从零开始 |

### Sinks（资源消耗/流失）

| 汇 | 消耗物 | 消耗速率 | 机制 | 备注 |
|----|--------|---------|------|------|
| 战斗-卡牌攻击 | 选中的方块×1/张 | 每次攻击1-3个 | 卡牌消耗 | **主要消耗口** |
| 建造-放置方块 | 选中的方块×1 | 每次放置1个 | 右键放置 | 次要消耗口 |
| 合成-配方消耗 | 配方所需材料 | 按配方表 | 合成系统 | 材料转换，非纯消耗 |
| 死亡-惩罚 | 无 | — | 当前无惩罚 | ⚠️ 设计缺口 |
| 装备损耗 | 无 | — | 当前无装备系统 | 未来扩展点 |

### 经济流向图

```
挖矿 ──▶ 物品栏 ──┬──▶ 战斗消耗（主要汇）
                  ├──▶ 建造消耗（次要汇）
                  ├──▶ 合成转换（中间态）
                  └──▶ 储备（无上限）

战斗掉落 ──▶ 物品栏 ──▶ （循环回到战斗）
```

### ⚠️ 经济系统问题诊断

| 问题 | 严重度 | 描述 | 建议修复 |
|------|--------|------|---------|
| **无死亡惩罚** | 🔴 高 | 玩家死亡不丢失物品，无风险感 | 死亡掉落50%携带物品 |
| **煤矿是唯一掉落** | 🟡 中 | 击杀敌人只掉煤矿，奖励单一 | 随机掉落：煤/铜/铁/稀有材料 |
| **物品无上限** | 🟡 中 | 物品栏无容量限制，无整理压力 | 限制99/格，超出无法拾取 |
| **合成不可逆** | 🟢 低 | 合成消耗材料但不可拆解 | 可接受，降低系统复杂度 |
| **拳击无成本** | 🟡 中 | 5伤害拳击不消耗任何资源 | 可接受作为fallback，但需限制使用频率 |

## 五、数值平衡验证路径

### 战斗数值表

| 参数 | 当前值 | 验证方法 | 平衡标准 |
|------|--------|---------|---------|
| 史莱姆HP | 30 | 3张无反应牌(30)恰好击杀 | ✅ 合理 |
| 基础伤害/牌 | 10 | 1张=10, 2张=20, 3张=30 | ✅ 线性增长 |
| 反应倍率 | ×2 | 3张有反应=60，秒杀30HP | ✅ 强烈但不必要 |
| 拳击伤害 | 5 | 需6拳击杀30HP史莱姆 | ✅ 慢但可行 |
| 敌人反击 | 6-11 | 玩家100HP，可承受9-16次反击 | ⚠️ 略低，后期无威胁 |
| 玩家HP | 100 | vs 反击6-11，可打9-16轮 | ⚠️ 对低伤害敌人过于安全 |
| 敌人接触伤害 | 8 | 非战斗时碰触扣8HP | ✅ 合理 |
| 敌人生成 | 夜晚0.5%/帧 | 最多8只 | ✅ 合理 |

### 平衡验证场景

#### 场景 A：新玩家第一夜（理想：紧张但不绝望）
```
玩家状态：HP 100, 物品栏：木板×5, 火把×4, 石头×10, 煤×2
敌人：史莱姆 ×2 (30HP each)

可选策略：
1. 全力攻击：3张牌(木板+火把+煤) = 燃烧反应 = 60伤害 → 秒杀
   消耗：木板1+火把1+煤1 → 剩余：木板4,火把3,煤1,石头10
   第二只：3张牌(木板+火把+石砖) = 无反应 = 30伤害 → 恰好击杀
   总消耗：木板2+火把2+煤1+石砖1 → 可持续

2. 保守拳击：6拳/只 = 12拳，每拳间隔反击6-11
   12拳 × (8.5avg反击) = ~102伤害 → 玩家死亡
   
验证结果：策略1可行且有趣，策略2不可行 → ✅ 鼓励使用材料
```

#### 场景 B：中期玩家 vs 多敌人（理想：需要策略选择）
```
玩家状态：HP 60, 物品栏：铁锭×3, 金锭×2, 钻石×1, 煤×5, 木板×8
敌人：史莱姆 ×3 (30HP each)

最优策略：铁+金=锈蚀(×2) → 3张=60 → 秒杀第一只
         铁+煤=导电(×2) → 3张=60 → 秒杀第二只
         钻石+煤=共振(×2) → 3张=60 → 秒杀第三只
         
消耗：铁3+金2+钻石1+煤3 → 高价值材料消耗
回报：3×煤矿 = 煤×3 → 净亏：铁3+金2+钻石1换煤3

验证结果：⚠️ 击杀回报不值消耗 → 需要增加掉落多样性
```

#### 场景 C：无物品死锁（理想：可脱困）
```
玩家状态：HP 30, 物品栏：空
敌人：史莱姆 ×1 (30HP)

拳击路径：5伤害/拳，需6拳
承受反击：6-11/次 × 6 = 36-66 → 玩家可能死亡

验证结果：⚠️ 高风险但可行 → ✅ 符合"无物品时紧张但不绝望"的设计目标
```

### 数值调整建议

| 调整项 | 当前 | 建议 | 理由 |
|--------|------|------|------|
| 敌人反击伤害 | 6-11 | 8-14 | 后期玩家HP 100时反击太低，缺乏威胁 |
| 敌人掉落 | 固定煤×1 | 随机：煤60%/铜25%/铁10%/金5% | 增加战斗奖励多样性 |
| 死亡惩罚 | 无 | 掉落50%随机物品 | 增加风险感，与"消耗即决策"支柱一致 |
| 拳击伤害 | 5 | 5（保持） | fallback不应太强，否则削弱材料系统价值 |
| 敌人HP种类 | 仅30HP | 史莱姆30/骷髅50/蝙蝠15 | 不同HP创造不同策略深度 |

## 六、Bug 排查报告

### Bug 1：Escape 键绕过 battleAnimating 🔴 已修复

**位置**：`game.js:217`
**问题**：Escape 键在对战时直接调用 `closeBattle()`，未检查 `game.battleAnimating`。而 overlay 点击事件(line 319)正确检查了 `!game.battleAnimating`。

**影响**：
- 击杀路径（800ms动画）：按Escape提前关闭面板，玩家看不到"🎉 击败敌人"反馈
- 非击杀路径（700ms反击延迟）：按Escape跳过反击，怪物存活但战斗结束。玩家以为怪物已死，实则怪物仍在世界中游荡

**修复**：添加 `!game.battleAnimating` 条件

### Bug 2：无物品时陷入死锁 🔴 已修复

**位置**：`executeBattleAttack()` + `drawBattle()`
**问题**：当玩家物品栏为空或已耗尽时，无法选择卡牌，攻击按钮永远 disabled。玩家只能逃跑，怪物存活。

**影响**：
- 新玩家在第一夜前未收集足够材料，遇到敌人后无法攻击
- 战斗中材料耗尽后陷入死锁

**修复**：添加"✊ 拳击(5)"按钮，固定5伤害不消耗物品，但有反击风险

### Bug 3：击杀路径的 setTimeout 竞态 🟡 低风险

**位置**：`executeBattleAttack()` 击杀路径
**问题**：击杀后 800ms 的 setTimeout 中，如果 `closeBattle()` 已被其他路径调用（修复前Escape），`game.enemies.indexOf(en)` 可能返回 -1。

**影响**：敌人不会被 splice，但由于 `en.health = 0`，`updateEnemies()` 的 `e.health <= 0` 检查会移除它。实际不影响击杀，只是路径冗余。

**状态**：Escape 修复后此问题不再触发，无需额外处理

## 七、后续设计方向

### 短期（Alpha → Beta）
1. **多样化敌人**：不同HP/伤害/元素弱点的敌人类型
2. **元素弱点系统**：特定敌人对特定元素伤害额外×1.5
3. **战斗掉落表**：按敌人类型和深度随机掉落不同材料
4. **死亡惩罚**：掉落部分携带物品

### 中期（Beta → Release）
5. **装备系统**：可装备的武器/防具，提供被动加成
6. **Boss 战**：多阶段、需要特定元素组合才能破防
7. **材料稀有度**：普通/稀有/史诗，影响伤害基数
8. **联机对战**：玩家 vs 玩家的卡牌对战

### 数值监控指标
- 平均每场战斗消耗材料数
- 拳击使用率（应<20%）
- 元素反应触发率（应30-50%）
- 玩家死亡率（应10-20%/夜）
- 平均探索深度随时间变化
